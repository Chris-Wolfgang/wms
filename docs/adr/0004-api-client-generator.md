# ADR 0004: API client generated with Kiota from the committed OpenAPI document

**Status:** Accepted (E82.8) · **Date:** 2026-09-20

## Context

The console (E82.4), the CLI (E82.6) and customer tools all talk to the one API (E82.1). Hand-written request
code drifts from the contract; the client must be generated from the OpenAPI document (E82.2), be AOT- and
trim-clean (E1.9: no reflection-based serialisation), version with the API, and be publishable to customers as
a package later. Client models are the wire contract; Domain records are mapped at the edge, so the client
must not depend on Domain.

## Decision

- **Generator: Kiota** (`Microsoft.OpenApi.Kiota`, Microsoft-maintained, MIT). Its generated code serialises
  through hand-rolled `IParsable` writers over `Microsoft.Kiota.Serialization.*`, with no reflection and no
  `System.Text.Json` polymorphism, so the client passes the trim/AOT analyzers that every `src/` project runs.
  Rejected: **NSwag** (reflection-based JSON, large runtime surface) and **Refit** (source-generated, but the
  interface is hand-written, so it is not driven by the spec).
- **Generated code is committed** under `src/Wolfgang.Wms.Client/Generated/` and regenerated by
  `scripts/Update-ApiClient.ps1` whenever `docs/api/openapi-v0.json` changes (`OpenApiDocumentTests` keeps
  that document equal to what the host serves). Committing keeps builds hermetic (no generator in CI's build
  path) and makes client changes reviewable in the PR that changes the API. A CI regeneration-drift check is a
  follow-up on the `openapi-diff` job.
- **One client per API version**: `WmsClient` in `Wolfgang.Wms.Client.Generated` for `v0`; a frozen `v1`
  (1.0) gets its own generated namespace and the package version follows the product.
- `Wolfgang.Wms.Client` references only the Kiota runtime (`Microsoft.Kiota.Bundle`), never Domain, Core or
  Infrastructure (`ClientIsolationTests`). `WmsApiClient.Create(HttpClient, IAuthenticationProvider?)` is the
  hand-written entry point; authentication providers (E11) plug in there.

## Consequences

- Adding an endpoint is: change the API, regenerate the spec (`WMS_UPDATE_OPENAPI=1`), run
  `Update-ApiClient.ps1`, commit all three. The PR shows the contract change and the client change together.
- The console gets typed request builders for free and never hand-writes a URL.
- Customers who cannot use .NET use the OpenAPI document directly; the package is a convenience, not the contract.
